# Chat and Widget Learning

## Interface principle

The learner experiences mathematics through a conversational stream containing short messages, buttons, answer choices, number lines, base-ten blocks, fraction builders, step sequencing, diagrams, graphs, confidence checks, and short animated explanations.

The app should not become a traditional course interface hidden behind a chat skin.

## Primary rule

> Never give a paragraph when the learner can understand by touching, moving, selecting, comparing, grouping, ordering, or constructing something.

## Teaching widgets

Widgets should explain as well as test.

Examples:

- drag one ten into the ones column;
- shade three of four equal parts;
- place a decimal on a number line;
- balance an equation;
- arrange problem-solving steps;
- identify an error in a worked solution;
- choose which representation matches an expression.

## Learner controls

- I do not understand;
- show me;
- give me a hint;
- make it easier;
- use smaller numbers;
- show with objects;
- show on a number line;
- explain another way;
- let me try;
- why does this work;
- challenge me.

## Assistance ladder

```text
Independent attempt
→ short prompt
→ strategic hint
→ guided step
→ interactive demonstration
→ worked example
→ imitation with new values
```

## Representation switching

```text
Objects
→ visual model
→ number line or diagram
→ table
→ symbolic notation
→ word problem
```

## Controlled rendering

The agent selects from trusted widget families and configures them. It does not generate unrestricted frontend code.
